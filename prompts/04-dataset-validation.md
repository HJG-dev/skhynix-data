# 범용 데이터 검증 프롬프트

아래 프롬프트를 복사해 데이터 분석 AI에게 사용할 수 있습니다. 대괄호 항목을 실제 미션·파일 정보로 채우고, 개인정보나 공개가 허가되지 않은 원자료는 외부 AI에 붙여넣지 마세요. 실제 값 대신 스키마·합성 샘플로 검토할 수 있습니다.

## 복사용 프롬프트

```text
역할: 데이터 품질 검토자. 주어진 파일의 구조와 분석 가능성을 확인하되, 관측되지 않은 사실이나 수치를 만들어내지 않는다.

미션/사용 목적:
[해결하려는 문제, 누가 결과를 사용할지, 결과가 쓰일 시점]

데이터 정보:
- 파일 경로 또는 이름: [경로]
- 출처와 이용 조건: [URL/기관/라이선스/접근일 또는 미확인]
- 한 행이 의미하는 관측 단위: [예: 사람-월, 주문, 이벤트 — 모르면 미확인]
- 기간·모집단·표본추출 방식: [아는 범위]
- 기대하는 입력과 결과: [목표 변수/분석 목적]
- 사용 환경: [로컬/승인된 서버/외부 AI 전송 금지 등]

요청:
1. 파일을 읽기 전에 민감정보, 비밀, 접근 조건을 확인한다. 실제 개인정보가 포함됐거나 외부 전송 허가가 불명확하면 내용을 노출하거나 외부로 보내지 말고, 스키마 수준 점검으로 전환하라고 알린다.
2. 원본을 수정·삭제·재인코딩하지 않는다. 검사 코드를 제안한다면 읽기 전용으로 만들고, 파생 처리가 필요하면 별도 출력 경로를 제안한다.
3. 파일 형식, 행·열 수, 컬럼명, 자료형, 단위·범주를 확인한다. 모르는 뜻은 추측하지 말고 질문으로 남긴다.
4. 결측, 완전 중복 행, 키 중복, 범위 위반, 불가능한 날짜/값, 단위 혼합, 범주 표기 불일치, 좌표계 혼합(해당 시), 인코딩·파싱 문제를 점검한다.
5. 관측 단위와 시간 순서를 확인해 중복 집계, 미래 정보 사용, 타깃 누수, 같은 사람/그룹이 학습·평가에 섞이는 문제를 찾는다.
6. 목표/라벨이 있다면 분포, 라벨 정의, 클래스 불균형, 라벨 누락과 생성 시점을 살핀다. 목표가 없거나 모호하면 임의로 만들지 않는다.
7. 출처·수집 시점·모집단·표본추출·포함/제외 기준·라이선스가 부족한 부분을 기록하고, 분석 결과에 미칠 수 있는 편향이나 대표성 한계를 분리해서 적는다.
8. 각 발견 사항을 심각도(차단/높음/보통/낮음), 영향, 확인 근거, 권장 조치, 조치 전후 비교 방법으로 표로 작성한다. 값이 실제로 계산되지 않았으면 수치를 쓰지 않는다.
9. 필수 오류와 단순 경고를 구분한다. 결측·이상치 제거를 자동으로 결정하지 말고 대안과 결과 영향 확인 방법을 제시한다.
10. 최종적으로 분석 가능/조건부 가능/현재는 부적합 중 하나를 근거와 함께 제안하고, 사람이 답해야 할 질문을 최대 5개 정리한다.

출력 형식:
A. 데이터 인벤토리와 확인 범위
B. 품질 점검표(심각도, 근거/실제 수치, 영향, 조치, 재검증 방법)
C. 누수·편향·개인정보·이용조건 위험
D. 우선 처리 순서와 원본/파생물 보존 계획
E. 분석 가능성 판단과 한계
F. 미확인 질문

중요: 실행하지 않은 검사는 실행했다고 말하지 않는다. 파일을 직접 읽지 못했다면 코드나 점검 절차만 제시하고 결과인 것처럼 서술하지 않는다. 통계적 연관성을 인과관계로 단정하지 않는다.
```

## 사람이 결과를 검토할 때

- 실제 파일과 미션 정의가 일치하는가?
- AI가 계산하지 않은 수치나 출처를 사실처럼 썼는가?
- 검사 기준이 도메인·단위·수집 방법에 맞는가?
- 행 제거·대체·정규화가 결과를 바꾸는 이유가 설명됐는가?
- 시간·그룹 누수가 평가 점수를 부풀릴 수 있는가?
- 민감정보와 이용 권한이 해결됐는가?
- 조치 전후 결과를 재현할 방법이 있는가?

검증 요약과 결정을 `templates/data-dictionary.md` 또는 `templates/analysis-plan.md`에 옮기고, 중요한 판단은 `docs/decisions.md`에 남깁니다. AI 답변 자체를 검증 증거로 간주하지 않습니다.
