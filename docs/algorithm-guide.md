# 해커톤 알고리즘 선택 가이드

주제가 정해지기 전에 특정 알고리즘을 정답처럼 고정하지 않습니다. 먼저 문제의 입력·출력·제약을 정의하고 단순한 기준선을 만든 다음, 필요한 유형만 골라 적용합니다. 아래 항목은 Git 저장소에 올려 팀원이 검토·재현할 수 있는 **알고리즘 구현 후보**입니다. 데이터, 출처, 라이선스, 실행 방법도 함께 기록하세요.

## 알고리즘을 고르는 공통 절차

1. **입력과 출력 정의:** 한 관측치가 무엇인지, 언제 결과를 알아야 하는지 적습니다.
2. **단순 기준선 설정:** 다수 클래스, 평균값, 기존 절차, 무작위/인기순 등 현실적인 비교 대상을 택합니다.
3. **제약을 반영:** 지연시간, 설명 가능성, 데이터 크기, 예산, 개인정보, 실행 환경을 적습니다.
4. **후보를 1~2개만 선택:** 데이터 규모와 성공 지표에 맞는 방법을 시험합니다. 라이브러리 이름만 나열하지 않습니다.
5. **같은 조건에서 비교:** 같은 데이터 분할·지표·전처리 조건에서 기준선과 비교합니다.
6. **오류를 살펴보고 결정:** 점수뿐 아니라 어떤 입력에서 실패하고 누구에게 불리한지 확인합니다.
7. **재현 정보를 남김:** 코드, 의존성, 설정값, 난수 시드(적용 시), 데이터 버전, 실행 명령을 기록합니다.

## Git에 올릴 만한 것

- 알고리즘의 입력/출력과 가정을 설명하는 모듈 또는 노트북
- 원본을 보존하고 파생 데이터를 별도 경로에 만드는 전처리 코드
- 데이터 출처·라이선스·버전·스키마 설명과 작은 합성 예제
- 기준선과 후보 알고리즘을 같은 평가 방식으로 비교하는 실행 코드
- 설정 파일, 의존성 잠금 파일(사용하는 언어 도구에 맞게), 실행 안내
- 실제 결과와 실패 사례를 요약한 문서

## 공개 전에 올리지 말 것

개인정보, 비공개 대회 데이터, 허가되지 않은 데이터·코드, API 키·토큰·비밀번호, 사용자별 로그, 접근 가능한 클라우드 주소를 커밋하지 않습니다. 공개 가능 여부가 불명확하면 파일을 추가하지 말고 출처와 규정을 확인합니다. 데이터가 비공개여도 스키마 설명과 합성 샘플만 공개할 수 있는지 규정을 확인합니다.

## 성능 지표는 문제에 맞게

- 회귀: MAE, RMSE 등. 큰 오차와 평균 오차 중 무엇이 중요한지 정합니다.
- 분류: 정확도 하나에 의존하지 말고 클래스별 precision/recall, F1, 혼동행렬을 봅니다.
- 순위·추천: Precision@K, Recall@K, NDCG 등 사용자 행동과 맞는 지표를 정합니다.
- 군집: 내부 점수만으로 유용성을 단정하지 말고 해석 가능성·안정성·업무 활용성을 검토합니다.
- 최적화: 제약 위반 수, 총 비용/거리/시간, 미배정 수, 해의 계산시간을 함께 봅니다.

**주의:** 모델 점수 상승만으로 제품 가치나 인과 효과가 입증되지는 않습니다. 표본과 수집 방식, 평가 조건을 함께 설명합니다.
